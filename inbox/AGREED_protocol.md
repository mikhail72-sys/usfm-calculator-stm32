# AGREED: протокол обмена USFM <-> читер, версия 1

**Зафиксировано:** 2026-08-25, device
**Канонический заголовок:** `C:\Piezus\TI\usfm\protocol.h` (компилируется и cl430, и VS2008 — брать копией, не переписывать руками)
**Правка этого файла:** любой стороной, с датой и автором.

## Транспорт

- UART **8N1, 250000 бод** по умолчанию (изм. 2026-08-26, device: потолок
  реального стенда — CP210x-485 адаптер 500000 не взял; 500000 остаётся
  зарезервированным на будущий адаптер). Адрес устройства **1**.
- Кадр как Modbus RTU: `[addr][func][payload...][crc_lo][crc_hi]`.
  CRC16 Modbus (полином 0xA001, старт 0xFFFF) по `addr..payload`.
- Конец кадра — **тишина ≥ 5 мс**. Полудуплекс, строгий запрос-ответ:
  читер спрашивает, прибор отвечает, одновременно никто не говорит.
- Прибор отвечает на свой адрес и на `0xFF` (опрос «кто на линии»).
- Ошибка: `[addr][func|0x80][код][crc]`, коды 1..6 как у Modbus/uslm.
- Все многобайтовые поля payload — **little-endian** (нативно для обеих сторон).

## Функции

### F17 — паспорт устройства
Запрос пустой. Ответ: `[len][usfmInfo]` — имя, версия прошивки, версия
протокола, capability-биты.

### F100 — сервисная (настройки), семантика uslm один-в-один
Payload запроса: `int16 reg; uint8 len; uint8 data[]`.
- `reg >= 0` — чтение `len` байт от регистра `reg`; ответ — сырые байты блока.
- `reg < 0` — запись `data[len]` от регистра `|reg|`; ответ — исключение
  с кодом 6 (BUSY) = «принято» (наследие uslm, сохранено сознательно).

Карта регистров v1 (блок = base + смещение в структуре, всё в protocol.h):

| base  | блок        | структура    | доступ |
|-------|-------------|--------------|--------|
| 100   | измерение   | usfmCfgMeas  | r/w    |
| 300   | порт        | usfmCfgSio   | r/w    |
| 400   | паспорт     | usfmInfo     | r/o    |
| 2000  | состояние   | usfmState    | r/w (управление через capture_ctl) |

RAW-буферы в карте НЕ живут — для них F101.

### F101 — RAW-данные АЦП
Запрос: `uint16 buf; uint16 off; uint16 len` (buf: 0=UPS, 1=DNS; off/len в
байтах, len ≤ 512). Ответ: `usfmRawHdr` (buf, off, len, **capture_seq**,
total) + сырые int16-выборки.
Семантика краёв (зафиксировано 2026-08-26): `off >= total` — ошибка
ADDRESS; `off+len > total` — КЛЭМП, отдаётся хвост, фактическое число байт
в `hdr.len` (прошивки < fw 1.10 отвечали ADDRESS — учтено читером).

Рецепт целостной вычитки: записать `capture_ctl=FREEZE` (или `SINGLE`),
прочитать `usfmState.capture_seq`, вычитать оба буфера кусками ≤512,
убедиться что `capture_seq` в заголовках кусков одинаковый, вернуть `RUN`.

### F102 — выстрел по команде (v2, 2026-08-26)
«Комп дирижирует»: запрос `usfmCmdMeasure {burst_type; first_dir; gain}` —
ручки на один выстрел. Прошивка берёт из блока 100 Lc_um/Cmin/Cmax и длину
пачки (npulses, f1), целочисленно считает окно приёма (мкм/(м/с)=мкс),
делает захват обоих направлений и отвечает `usfmMeasureReply {status;
capture_seq; sample_size; adc_start_us; capture_us}` ПО ЗАВЕРШЕНИИ —
ответ и есть признак готовности, дальше забирать F101 (freeze не нужен:
F102 сам переводит фон в FREEZE). Вернуть фоновую синтетику — записать
RUN в state.capture_ctl. status: bit0 = окно обрезано по RAM,
bit1 = кривые параметры (захвата не было). Размер захвата всегда кратен
4 выборкам (требование USS-библиотеки). Пока захват — синтетика, но
форма огибающей следует burst_type (треугольник / два горба / чирп
с ползущей частотой f1->f2) — можно обкатывать распознавание форм.

Блок 100 v2: бывший reserve[4] стал lc_um (uint32, мкм), cmin_mps,
cmax_mps (uint16, м/с). Смещения прочих полей не менялись. proto_ver = 2.

### Статусные биты F102 (usfmMeasureReply.status)
| бит | имя | смысл |
|-----|-----|-------|
| 0x0001 | CLIPPED | окно приёма обрезано по объёму RAM (512 выборок) |
| 0x0002 | BADPARAM | параметры блока 100 кривые, захвата не было |
| 0x0004 | SYNTH_DATA | в буферах синтетика, не АЦП (захват не удался или не реализован) |
| 0x0008 | PPG_FAIL | USS/PPG/SDHS не отработал; код ошибки в reply.reserve (1=кварц, 2=busy, 3=частота, 4=powerup, 5=capture) |
| 0x0010 | MONO_ONLY | запрошен верблюд/чирп, но физически улетел MONO (XPG ещё не подключён) |

Бит 0x0004 снят = в буферах настоящий АЦП. С fw 1.10 прошивка стреляет и
захватывает по-настоящему (кювета на стенде в отладке).

### Коды усиления (gain) — PGA тракта приёма, кодировка USS-библиотеки
Диапазон 17..63, шаг ~0.9 дБ: 17 = −6.5 дБ, 25 = +0.1 дБ, 32 = +6.0 дБ,
40 = +12.2 дБ, 50 = +20.5 дБ, 55 = +24.6 дБ, 63 = +30.8 дБ (максимум).
Формула на глаз: дБ ≈ (код − 25) · 0.93. Полная таблица — enum
USS_Capture_Gain_Range в ussSwLib.h библиотеки USS.

### Фоновая синтетика и серии F102
F102 сам переводит capture_ctl в FREEZE — фон (meas_per_sec) с этого
момента буферы не трогает. Серию F102 можно гнать, не выключая фон:
заморозка происходит на первом же выстреле. RUN возвращается записью в
state.capture_ctl.

## Бюджет скорости (ориентир)

500 кбод ≈ 50 КБ/с полезных. Захват ~250 выборок × 2 байта × 2 направления
≈ 1 КБ → с накладными и разворотами линии ~15–25 полных кадров АЦП в
секунду. Для стенда «смотреть эволюцию огибающей» достаточно; резерв —
поднять baud через блок 300 (прошивка сможет 1 Мбод, упрётся в адаптер).

## Версионирование

`usfmInfo.proto_ver` = 1. Поля и коды не переименовываются и не двигаются;
расширение — только новые поля в хвост блоков (в зоне reserve) и новые
функции, с инкрементом proto_ver.

### Формы возбуждения — финал (2026-08-26, fw 1.20)
- 0 MONO: npulses@f1.
- **1 и 2 — синонимы**: двухчастотная пачка npulses@f1 + npulses@f2 встык
  (обе частоты из блока 100). «Верблюд с паузой» и плавный DMA-чирп
  отменены решением босса («не усложняем»); поле pause_cycles блока 100
  зарезервировано.
- F102: reserve2 стал **dir_gap_us** — пауза между направлениями внутри
  выстрела, мкс (0 = дефолт 200, кламп 50..5000). Ручка для промера
  систематики второго направления (запрос analyzer).

### Код Баркера (2026-08-27, fw 1.30, proto_ver 3)
- **burst_type = 3**: фазокодированная посылка на f1, чип = npulses
  периодов, код длины **barker_len** (новое поле блока 100, смещение 32:
  uint16, допустимые 2,3,4,5,7,11,13; прочее прошивка молча приводит
  к 13; дефолт 13).
- **Длины 2/3/4 — штатные** (вид "+..+-", один инвертированный чип в
  конце): ложатся на аппаратные стоп-импульсы PPG (фаза 180 без всяких
  растяжек), захват обычным ASQ-путём, качество как у MONO/DUAL.
  npulses 1..15, рекомендация 1..2. Проверено по эху МНК-моделью
  (эталон = эхо одиночного импульса): код +++- читается, corr 0.965.
- **Длины 5/7/11/13 — экспериментальные**: секции XPG перезаряжает
  DMA-цепочка (механика библиотечного мультитона), скачки фазы —
  растяжка низкой фазы на per/(2*npulses) на каждый импульс чипа перед
  сменой знака; npulses 2..4 (единица не тянет темп перезарядки).
  Посылка формируется и штатно останавливается терминальной XMOD_2
  (видно осциллографом и по диагностике в reserve блока 2000), но
  захват для них вынужденно РУЧНОЙ — под ASQ кристалл не выдаёт
  DMA-события границ секций (аппаратное ограничение, раскопано
  бисекцией: глушит именно UUPSCTL.ASQEN), а ручной приёмный тракт
  пока болен легаси-болезнью (постоянка ~-1800 кодов, эха в данных
  нет). До вылечивания тракта длинные коды — только для осциллографа.
- npulses=1 для длин 5+ и barker_len=3 в старых билдах: F102 отвечает
  PPG_FAIL (reserve=3, частота/параметры).
- Побочный диагноз: этой же парой причин (ASQEN + запертый SAPH,
  глотающий DMA-записи) болел отменённый чирп.

### Напряжение возбуждения — в ВОЛЬТАХ (2026-08-28, fw 1.40, proto_ver 4)

Прибору задаётся напряжение, а не PWM-код: «как смогу, так и выставлю».
Характеристика повышайки снята Fluke 289 прямо на плате: полка 11.83 В до
кода ~20, дальше линейно V = 10.135 + 0.0829*код до 30.02 В на коде 240
(шаг кода 83 мВ).

Блок 100 (стал 38 байт), аддитивно в хвост:
- `hv_mv` (uint16, мВ) — рабочее напряжение, 0 = повышайку не трогать;
- `hv_cal_lo_mv` (uint16) — вольты при коде 21, дефолт 11875;
- `hv_cal_hi_mv` (uint16) — вольты при коде 240, дефолт 30023.
Калибровка в настройках нарочно: другая плата — перемерили вольтметром
два конца шкалы и записали, прошивка не меняется.

F102: `usfmCmdMeasure` += `hv_mv` (мВ, на выстрел);
`usfmMeasureReply` += `hv_mv` — что РЕАЛЬНО выставлено (округление до кода).
Приоритет: hv_mv команды > hv_code команды (старый путь, совместимость) >
hv_mv блока 100. Вне шкалы — прижимается к концам, ответ честный.

Поверено против Fluke 289 в точках 12..30 В: расхождение «прибор против
вольтметра» <= 4 мВ, отклонение от заказанного <= половины шага кода.

### Скорость и темп (2026-09-01, fw 1.50, proto_ver 5)

- **F103 MEASURE_RAW**: запрос = usfmCmdMeasure, ответ одним кадром
  `[addr][103][usfmMeasureReply][UPS n*2][DNS n*2][crc]`, n =
  reply.sample_size из этого же кадра (0 при BADPARAM — данных нет).
  Одна транзакция вместо F102+2xF101: x4.2 на 250 кбод, дальше — больше.
- **meas_per_sec**: 0 = стоп, 1..32 = по таймеру (тик 32 Гц), >32 =
  свободный бег «сколько сможешь». Замерено: 668 пар/с на v1-конфигурации,
  повышайка не проседает.
- **Смена baud с автооткатом**: запись в блок 300 применяется сразу
  (квитанция уходит на старой скорости), но если за 5 с на новой скорости
  прибор не услышал ни одного валидного кадра — откат на прежнюю.
  Лесенку скоростей можно щупать без риска потерять связь.
- Белый список бодов: 9600, 19200, 38400, 57600, 115200, 250000,
  460800*, 500000, 921600*, 1000000. Помеченные * имеют на плате ошибку
  делителя ~2% (16 МГц без оверсемплинга) — ставку делать на 500к и 1М
  (делители точные), упор в адаптер: CP210x — только 250к, CH340 — обе.

### Вычислитель STM32 по I2C (2026-09-03, fw 1.60, proto_ver 6)

- **I2C-ведомый MSP430**: eUSCI_B0, адрес 0x0A, SDA P1.6 / SCL P1.7,
  подтяжки 4.7к на плате; DRDY MSP→STM на PJ.7 — уровень «1 = есть
  невычитанный кадр», снимается по полному чтению ответа.
- Транзакции: запись мастера = кадр протокола целиком
  `[addr=1][func][payload][crc16]` (до 64 байт нагрузки); чтение мастера =
  `[len_lo][len_hi]` + ответный кадр `[addr][func][...][crc16]`. Пока ответ
  считается — ведомый держит SCL (стретчинг, таймаут мастера ≥ 50 мс);
  нечего читать — len 0. Ответ любой длины одной транзакцией (сегменты
  без копирования).
- **F104 GET_FRAME**: пустой запрос, ответ = формат F103 для ПОСЛЕДНЕГО
  завершённого захвата (без выстрела) — путь вычислителя в штатном фоне.
- `usfmMeasureReply` += `frame_flags` (биты 0-1 burst_type, 2 first_dir,
  3 hord) — какой формой снят кадр.
- Блок 100 += `burst_type_b` (0xFFFF = выкл): чередование двух форм
  A/B в фоне, выстрел за выстрелом.
- **Блок 3000 `usfmCalcResult`** (28 байт, r/w, пишет STM32): tof_ups_ps,
  tof_dns_ps (uint32, пс), dtof_ps (int32), capture_seq, frame_flags,
  status (1 VALID, 2 NOSIGNAL, 4 COMPRESSED), quality, flow_lph (int32,
  0 = не считает), reserve. Экран и частотный выход MSP читают отсюда.
