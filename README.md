# usfmcalcv0

Прошивка STM32-«вычислителя» расходомера USFM: MSP430 остаётся
измерителем (C:\Piezus\TI\usfm), обработка и частотный выход уезжают
на STM32 по I2C. Контроллер для серии ещё не выбран, поэтому дерево
устроено как в uslm5lp0v3: общий код в корне, по каталогу на каждый
MCU-вариант.

## Состояние: этап 1 «транзит» (fw 0.10, 2026-09-03)

Кадры F103/F104 с MSP430 по I2C (STM32 мастер, 400 кГц, DRDY на PB5)
уходят на PC в USB-поток записей по `inbox/AGREED_usb-stream.md`.
Команды PC→STM: `[len16][addr][func][payload][crc16]`; addr 2 =
вычислитель (F17, F100 регистры с базы 4000, F105 сырой I2C-пробник),
addr 1 = мост на MSP430 (кадр уходит по I2C как есть, ответ verbatim).
Имитатор кадров (source=1) для отладки приёмника без прибора.

Проверено живьём с MSP fw 1.60: фон 10 кадр/с — 38 кадров за 5 с без
ошибок CRC; имитатор 100 кадр/с — без потерь. Эталонный приёмник и
стенд-тест: `pc\calctest.ps1 -Port COM7 -Source i2c -MspRate 10`.

Файлы этапа 1: `usfm_link.c/.h` (кадры по I2C, CRC16), `stream.c/.h`
(записи потока, регистры вычислителя), `cmd.c/.h` (командный канал,
мост), `sim.c/.h` (имитатор), `F411_main/kernel_f411.c` (I2C-мастер с
таймаутами и восстановлением шины).

Грабли ведомого (fw 1.60), учтены в коде: ответ не готов в первые ~сотни
мкс после STOP (пауза 2 мс перед чтением, `I2C_REPLY_DELAY_MS`); каждый
START перезапускает ответ с префикса длины; на 100 кГц длинный кадр
рвётся, потому что MSP перезаписывает RAW-буферы во время чтения.

## Было: v0 (2026-09-03, утро)

Пустое приложение для STM32F411CEU6 (плата WeAct «black pill»):

- тактирование 96 МГц от HSE 25 МГц, USB 48 МГц, SysTick 1 мс;
- USB CDC-ACM (виртуальный COM-порт), VID:PID 0483:5740 — Windows
  подхватывает штатный usbser без драйвера;
- тестовый режим: **эхо** — всё принятое отправляется обратно байт в
  байт; при открытии порта печатается баннер; нажатие KEY (PA0) даёт
  строку `KEY`;
- светодиод PC13: мигает 1 Гц — USB не сконфигурирован; короткая
  вспышка раз в секунду — порт не открыт; горит постоянно — порт открыт,
  гаснет на 30 мс при обмене.

Проверено живьём 2026-09-03 (black pill, ST-LINK V3, st-flash):
плата видна как «STMicroelectronics Virtual COM Port», серийник
USFMCALC-0001; эхо байт в байт на блоках 63..4096 Б, 256 КБ непрерывно —
442 КБ/с туда-обратно без потерь, при остановке чтения на PC поток
встаёт (NAK) и после вычитки данные целы.

## Сборка и прошивка

    cd F411_main
    make            (или mk.bat; ошибки в err.txt)

Загрузчика пока нет, образ лежит с 0x08000000:

    make swdflash   -- ST-LINK (st-flash)
    make dfuflash   -- ROM DFU: зажать BOOT0, ткнуть NRST; нужен dfu-util

Мастер-makefile `../masterF4.mk` (hard-float, --gc-sections), библиотека
`../libopencm3.my`. Карта секторов флеша и план под загрузчик/конфиг —
в комментарии `F411_main/MY_FLASH.ld`.

## Проверка эха

Открыть COM-порт любым терминалом (115200, параметры не важны), набрать
текст — он возвращается. Для бинарной проверки: послать файл, сравнить
принятое. При переполнении приёмного буфера устройство NAK-ает хост,
байты не теряются.

## Файлы

    usb_vcp.c/.h      CDC-ACM поверх libopencm3 usbd (polled)
    kernel.h          API железа, который реализует каждый MCU-каталог
    F411_main/        Makefile, MY_FLASH.ld, startup.c, config.h,
                      pins_f411.h, kernel_f411.c, mk.bat
    inbox/            входящие от соседних проектов (правила внутри)

## Грабли

- PA9 на black pill не соединён с VBUS, а OTG-инициализация libopencm3
  включает VBUS-сенсинг: без `KernelUsbPostInit()` (NOVBUSSENS) хост
  устройство не увидит.
- Библиотека F4 собрана под hard-float ABI: без `-mfloat-abi=hard`
  приложение не линкуется.
